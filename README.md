# 제주 POI 데이터 구축과 운영 상태 자동화

제주 지역 POI(Point of Interest) 데이터를 수집·통합·정제하고, 운영 상태를 안전하게 판정해 서비스 업로드 파일로 내보내는 프로젝트입니다.

이 저장소는 최신 Airflow 배포 코드와 실행·인수인계 문서를 중심으로 정리했습니다. 원본 CSV와 대용량 행정·카카오 증거 JSONL은 Git에 넣지 않고 별도 실행 패키지 ZIP으로 전달합니다.

## 프로젝트 결과

최신 기준 57,989개 원본 행을 보존해 아래 상태로 분류했습니다.

| 상태 | 건수 | 의미 |
|---|---:|---|
| 영업 | 35,890 | 지도·행정 근거상 서비스 유지 대상 |
| 운영 | 14,842 | 고정 공공·인프라 시설 등 변경 근거 없이 유지 대상 |
| 확인 필요 | 5,675 | 카카오 미발견 또는 행정 후보 미해결 |
| 폐업 | 1,582 | 명시적 행정 원천 폐업 근거 확인 |
| 전체 | 57,989 | 원본 행 보존 |

서비스 업로드 대상은 영업·운영을 합한 50,732건입니다.

## 상태 판정 원칙

1. 명시적 행정 원천의 폐업 근거가 있을 때만 폐업 처리합니다.
2. 카카오 검색 미발견만으로는 폐업 처리하지 않고 확인 필요로 둡니다.
3. 카카오 후보는 이름, 주소, 장소 역할이 모두 같은 경우에만 동일 장소로 인정합니다.
4. 행정 원천 후보가 여러 개여서 동일 장소를 확정하지 못하면 확인 필요로 둡니다.
5. 공공·고정·인프라 시설은 공식 변경 근거가 없으면 운영으로 유지합니다.
6. ATM, 충전소, 주차장, 세차장, 공중화장실처럼 역할이 다른 부속 시설은 본 매장과 매칭하지 않습니다.

## 검증

- 자동 테스트 56개 통과
- 서비스 파일에는 영업·운영만 포함되는지 검증
- 전체 상태·판정보존 파일의 행 수와 상태값을 검증
- 폐업 판정이 고정시설·인프라 예외 규칙을 위반하지 않는지 검증

## 보안과 대용량 데이터

- Kakao REST API 키는 코드나 Git에 넣지 않고 환경 변수로 주입합니다.
- 실행용 원본 CSV와 증거 JSONL은 별도 인수인계 ZIP에 포함합니다.
- ZIP 안의 `env.example`을 복사해 키를 설정한 뒤 `RUNBOOK.md` 절차를 따릅니다.
